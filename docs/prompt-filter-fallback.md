# Prompt 违规直达兜底池

在 `/admin/prompt-filter/overview` 的「管理防护 → 本地执行策略」选择「兜底」并保存。系统设置中的 Prompt 模式也提供同一选项，持久化值为 `prompt_filter_mode=fallback`，无需数据库迁移。

- 本地规则或模型复核最终判定应拦截时，跳过主池，使用已启用的兜底池；正常请求仍走原路由。
- 兜底沿用现有账号筛选、模型映射、并发和终态请求处理。兜底池没有匹配账号或请求失败时返回错误，不回主池。
- 支持 HTTP Responses、Responses Compact、Chat Completions、Messages，包括流式请求；Responses WebSocket 每轮独立判定。
- 仅审核服务超时或故障不算违规，仍执行「模型复核策略」中的失败放行或失败拦截。本地已经独立确认违规时，审核故障不会清除本地判定。
- 携带 `previous_response_id`、已绑定上游的续接或压缩状态不能直接迁移到另一供应商，继续拦截。没有兜底执行器的图片、视频、Realtime 等入口，以及主池账号选定后发生的二次检查，继续拦截。
- 已有会话锁定和 NewAPI 身份要求仍按原规则执行。成功选择转兜底策略的违规请求不会新增本地会话锁。
- 兜底模式同步产生违规判定，优先于旧高级配置中的观察模式。其他执行模式保持原行为。

Prompt 日志中「转兜底」表示选择了兜底处理策略，不保证供应商最终响应成功。请求/接力日志通过 `content_review`（Prompt 违规）记录实际兜底原因和请求结果。
